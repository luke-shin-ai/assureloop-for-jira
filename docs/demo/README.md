# The no-install demo

Open `index.html` in a browser. That is the whole install. There is no server, no build step at
view time, no Atlassian site, and the page makes no network request: `data.js` beside it is the
only data it reads.

`https://luke-shin-ai.github.io/assureloop-for-jira/demo/` serves the same three files from GitHub
Pages (branch `main`, folder `/docs`).

## What it shows

| Surface | What a visitor can do |
|---|---|
| Control room | The last scan's five counts, the programme's binding, and all twenty claims with their state, evidence link, observation time and freshness window |
| Any claim, `Why?` | The read that produced the verdict, hop by hop, with the node, the relation, the ARI and the observation time, and the `queryKey` footer |
| Evidence panel | PAY-1 judged live against four claims, the product's front door |
| Audit pack | The workpaper: twenty rows, a SHA-256 fingerprint, **Verify fingerprint** (recomputed in the browser over the rows on the page) and **Copy the audit memo** |
| Trust boundary | What the pack guarantees and what it does not, collapsed to one line above and below the page, with **Show all** |

## Why the numbers are the app's numbers

`data.js` is generated by `npm run build:demo` (`scripts/build-demo.mjs`), which imports the
shipped programme from `src/seed/northwind-pay.ts` through esbuild. Controls, claims, evidence
types, windows and the exception carry over unchanged. The states are the ones measured on the
demo site on 2026-11-20 (18 verified, 1 stale, 1 missing), and `npm run check:claims` fails if the
page, the seed, the fingerprint field list or the verdict counts disagree.

The fingerprint on this page is a real SHA-256 over the twenty rows the page shows, computed with
the same field list (`FINGERPRINT_FIELDS` in `src/audit/pack.ts`) and the same serialisation on
both sides: Node at build time, the browser when you press **Verify fingerprint**. It is a digest
of this page's rows, not the app's 2026-11-20 pack value, and the page says so.

## Measuring it

```bash
npm run build:demo                 # regenerate data.js
npm run test:demo                  # Playwright: 1440, 1920 and 390x844
```

`scripts/check-demo.py` asserts, at each viewport, that `documentElement.scrollWidth` and
`body.scrollWidth` do not exceed `innerWidth`, that no element crosses the viewport edge, that
twenty claim rows and five counters render, that `Why?` opens a trace, that **Verify fingerprint**
returns VERIFIED MATCH, and that **Show all** expands and collapses. It saves
`../screenshots/pages-desktop-ux.png` and `../screenshots/pages-mobile-ux.png`.

Playwright's Chromium needs its system libraries; on a machine where the bundled browser cannot
find `libnspr4.so`, point it at a sysroot that has them
(`LD_LIBRARY_PATH=/path/to/sysroot/usr/lib/x86_64-linux-gnu`).
